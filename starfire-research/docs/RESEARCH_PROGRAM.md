# Starfire Research Program

## Objective

Starfire investigates whether a cognitive architecture can create **auditable, typed, executable intermediate state** that changes later computational capability, rather than merely preserving transcript context.

The program is organized as a sequence of narrow falsification experiments. Each experiment attacks one privileged assumption left by the previous result.

## Experimental discipline

A result is considered scientifically usable only when the following are frozen before the first verdict-producing run:

- task construction;
- train, holdout, and future families;
- operation budget;
- controls;
- scoring law;
- acceptance thresholds;
- replay requirements;
- terminal classification rules;
- claim boundary.

A failed experiment is not tuned after observation and then presented as confirmation. A corrected mechanism requires a new preregistered experiment.

## Required controls

Depending on the mechanism, experiments include matched paths that preserve compute while destroying the proposed causal factor:

- endpoint execution without state admission;
- proof or frontier text without executable mutation;
- scalar summaries without executable mutation;
- same-root incidence destruction;
- foreign or rewired proof submission;
- structurally valid but objective-irrelevant mutation;
- counterfeit proof fields;
- delayed admission after the search window;
- representation- or frontier-tampering controls.

The purpose is not merely to show that the stateful path succeeds. It is to show that the claimed intermediate state is causally necessary under a matched budget.

## Independent validation boundary

The proposer must not receive the held-out objective, hidden correct rule, family label, split label, future outcome, or control identity.

The validator independently recomputes the relevant evidence statistics and issues an opaque certificate only when the frozen contract passes.

The external objective checker receives only the final executable state and the expected objective atom. It does not read self-reports, prose explanations, path labels, or confidence statements.

## Determinism

Every root and path is executed twice from a freshly reconstructed state. Exact replay must include:

- inferred rule or error;
- proof fields;
- validation decision;
- budget counters;
- objective result;
- canonical executable-state signature.

H8 demonstrated why this requirement matters: resolver-internal unordered iteration changed emitted text and downstream objective scores across unchanged process executions. The result was classified as `CONTROL_FAILURE`, and the apparent scientific conclusion was withdrawn.

## Program progression

### H4-H6: signal without justified executable ontology

The early program tested whether memory-associated residuals, task-profiled verification, or resolver disagreement exposed a stable latent concept suitable for automatic promotion.

They did not. The evidence did not justify live routing or automatic ontology induction.

### H7: continuation and right absorption

H7 tested whether state-threaded resolver continuation revealed a stable higher-order distinction beyond one-step behavior. The result was negative, with a high rate of right absorption: later operations mostly overwrote or ignored earlier computational transformations.

This suggested that preserving history was not enough. The architecture needed a typed state-transforming substrate.

### H8: deterministic semantics failure

H8 attempted an action-order experiment but discovered that internal `HashSet` iteration affected actual reasoning output. Identical seeded runs produced different prompt bytes and objective scores.

The scientific lesson was architectural: a seeded environment does not define a deterministic computational operation when resolver internals remain unordered.

### H9: Proof-Carrying Executable Commitment State

H9 introduced PECS:

- immutable raw observations;
- typed fact and rule commitments;
- validation-gated state deltas;
- provenance for each derived commitment;
- deterministic canonical derivation order;
- replay-stable state signatures.

H9 passed across training, holdout, and future vocabularies. Only the path that admitted the validated executable commitment reached the objective.

### H10: evidence-bound induction

H10 removed the directly witnessed target bridge. The useful rule had to be inferred from a finite, target-blind intervention table.

The proposer emitted an auditable proof. The validator independently recomputed all candidate scores. Only an opaque validated certificate could create an executable rule.

H10 passed. Text, scalar, foreign-proof, counterfeit, delayed, endpoint-blind, and valid-but-irrelevant controls failed to reach the objective.

### H11: graph-discovered candidate frontier

H11 removed H10's explicitly supplied antecedent and consequent candidate lists.

The mechanism discovered eligible relation endpoints from graph incidence, constructed a 6×6 candidate frontier, scored all 36 relations, and survived independent frontier rediscovery and proof recomputation.

H11 passed across unseen vocabularies. A frontier-tampering control was rejected on every root, and a valid but irrelevant discovered rule was admitted on every root without reaching the objective.

## Next research gate

The strongest remaining privileged boundary is developer-defined representation and induction law.

The next experiment should require **evidence-derived structural abstraction**:

1. observe graph motifs across training roots;
2. induce reusable structural roles or relation classes without target labels;
3. freeze the learned abstraction before holdout evaluation;
4. generate candidate executable relations for unseen graph families;
5. independently validate abstraction provenance, candidate generation, evidence ranking, and admission;
6. preserve matched budgets and all causal controls.

A positive result would still not establish open-world reasoning or AGI. It would support a narrower claim: learned structural abstractions can generate causally useful executable candidates under controlled transfer.

## Publication rule

Every published result must include:

- preregistration identity;
- first verdict-producing implementation identity;
- terminal classification;
- complete path-level result table;
- exact compute contract;
- replay status;
- invariant status;
- strongest supported claim;
- explicit non-claims;
- strongest remaining limitation.
